# MAGTOPIA（麦托邦）核心玩法设计

## 文档状态

- 版本：v0.1
- 状态：核心玩法基线，供模拟、服务端和 Agent 开发参考
- 适用范围：资源、人口、建筑魔法程度、建筑级暴露、实时推进、卡片和猫头鹰日报
- 不包含：完整科技树、职业系统、多人城市、复杂外交、独立的里层/外层城市

## 1. 核心体验

MAGTOPIA（麦托邦）是一款由 AI Agent 驱动的近等距俯视视角魔法城市建设游戏。

玩家和 Agent 不需要持续处理每一个城市问题，而是分别承担不同节奏的职责：

- 玩家通过偶发的卡片选择改变城市方向、处理关键时刻或接受风险。
- Agent 负责持续建设城市、安排住宅和公共建筑、改善高魔法建筑周围的掩护结构。
- 系统按照真实世界时间持续运行，自动结算资源、人口、建筑事件和魔法部响应。
- 系统每天生成一篇纯文字的“猫头鹰日报”，总结上一天实际发生的变化。

核心矛盾是：

> 魔法程度越高，城市越能吸引魔法师并产生魔力；但高魔法建筑也越难隐藏，需要普通建筑提供掩护。暴露失控不会导致 Game Over，而会让对应建筑永久变成城市中的都市传说地点。

## 2. 设计原则

### 2.1 资源精简

不使用木材、石材、食物、煤炭等多种建造资源。基础经济只保留金币和魔力；人口以容量和当前人口表示。

### 2.2 建筑是主要玩法单位

暴露度、生产、人口容量和魔法师吸引力都以建筑为中心计算。城市不使用一个全局暴露度来决定失败。

### 2.3 风险应当留下城市记忆

处理失败不摧毁城市，而是永久改变一栋建筑和一块地块。封锁建筑仍然保留在地图上，成为围栏、封条、闲置结构和城市故事的一部分。

### 2.4 观察和规划胜过微操

系统自动派遣魔法师处理暴露事件。玩家和 Agent 的重点是布局、扩张、卡片决策和风险管理，而不是逐个点击处理事件。

### 2.5 时间持续流逝

回合不是暂停。回合只是日报和决策的节奏单位。没有人操作时，城市继续生产、迁入人口、产生事件和完成建设。

## 3. 基础经济

MAGTOPIA 的四个基础元素分为普通侧和魔法侧：

| 侧别 | 变量 | 含义 |
|---|---|---|
| 普通侧 | 金币 `coins` | 建造、维护、公共事务和舆论处理的通用货币 |
| 普通侧 | 普通人口 `mugglePopulation` | 当前普通市民数量与普通人口上限 |
| 魔法侧 | 魔力 `magic` | 建造和运营魔法建筑的统一魔法资源，也代表魔法材料供给 |
| 魔法侧 | 魔法师人口 `wizardPopulation` | 当前魔法师数量与魔法师人口上限 |

人口不是需要逐个搬运的物资，但需要区分当前值和上限：

```json
{
  "coins": 820,
  "magic": 37,
  "population": {
    "muggles": { "current": 31, "capacity": 40 },
    "wizards": { "current": 5, "capacity": 8 }
  }
}
```

### 3.1 基础缓慢增长

即使城市没有生产建筑，金币和魔力也有很低的基础增长，避免玩家因短期失误完全卡死：

```text
基础金币收入：+4 / 日
基础魔力收入：+1 / 日
```

基础收入只提供启动能力，不能替代生产建筑。

### 3.2 建筑产出

公共建筑根据自身的魔法程度和类型，提升金币或魔力生产能力：

- 普通公共建筑主要生产金币、提供普通人口服务和掩护。
- 中低魔法公共建筑可以同时生产少量金币和魔力。
- 高魔法公共建筑主要生产魔力、吸引魔法师，但暴露压力较高。

建筑生产受到以下因素影响：

- 建筑是否处于 `active` 状态
- 建筑是否有足够人口或岗位
- 建筑的魔法程度
- 建筑是否被封锁
- 卡片产生的临时修正

被封锁的建筑不再生产任何资源，也不再提供人口上限。

## 4. 建筑与魔法程度

每栋建筑拥有 `magicLevel`，范围为 `0–1`。该参数同时影响建筑的玩法和视觉表现。

| `magicLevel` | 建筑表现 | 主要作用 |
|---:|---|---|
| 0.00–0.20 | 完全普通 | 强掩护，普通人口和金币侧建筑 |
| 0.20–0.50 | 有少量异常细节 | 普通功能为主，提供有限魔法价值 |
| 0.50–0.80 | 明显魔法建筑 | 提供魔力、魔法师岗位和较高吸引力 |
| 0.80–1.00 | 高强度魔法建筑 | 极高吸引力和产出，但需要大量掩护 |

现有体素建筑系统中已有魔法程度相关参数和魔法视觉元素。后续应优先让 `magicLevel` 统一驱动：

- 魔法窗、符号、灯光和装饰出现概率
- 魔法颜色和发光强度
- 建筑尺寸、层数和基础建造成本
- 魔法师吸引力
- 魔力产出或消耗
- 建筑级暴露压力

魔法建筑不需要单独的“里层城市”。它们仍然位于普通城市中，并通过建筑外观、邻域掩护和低调公共功能保持隐秘。

### 4.1 建造成本

普通建筑主要消耗金币。魔法程度超过普通阈值的建筑需要金币和魔力：

```text
金币成本 = 基础金币成本 × 建筑面积 × 魔法程度系数
魔力成本 = 基础魔力成本 × 建筑面积 × 魔法程度
```

高魔法住宅通常更大，因此同时具有：

- 更高魔法师人口上限
- 更高金币成本
- 更高魔力成本
- 更高暴露压力

## 5. 人口系统

### 5.1 普通人口

普通住宅提供普通人口上限。普通人口支持：

- 普通公共建筑运营
- 市场和服务消费
- 金币生产
- 对魔法建筑的社会掩护

普通人口上限不足时，普通建筑可能无法满负荷运行，城市金币产出下降。

### 5.2 魔法师人口

高魔法住宅提供魔法师人口上限。魔法师支持：

- 魔法公共建筑运营
- 魔力生产
- 魔法建筑的吸引力和效率
- 魔法部的自动事件处理能力

魔法师人口不是消耗品。魔法部派遣的是当前魔法师中的可用处理能力。部分魔法师可能已经在建筑岗位工作，因此可用于事件处理的数量会低于总人口。

## 6. 建筑级掩护与暴露度

### 6.1 设计目标

不计算城市级暴露度。每栋建筑有自己的暴露状态，附近建筑只影响它的掩护值。

玩家应该能直接理解：

> 这座建筑危险，是因为它太魔法，而附近没有足够普通、热闹、合理的城市功能来解释异常。

### 6.2 掩护值

低魔法建筑是掩护，不需要建造专门的“掩护建筑”。不同建筑提供不同掩护能力：

- 普通市场、剧院、车站、学校：强掩护
- 普通住宅：中等掩护
- 普通工坊和商店：中等掩护
- 公园和空地：弱掩护
- 高魔法建筑：不提供普通掩护，可能增加邻近风险

建筑的掩护只计算有限邻域，例如相邻一圈或两圈地块。掩护值是派生值，不作为额外资源储存。

```text
邻域掩护值 = 附近建筑的掩护能力 × 距离权重 × 建筑当前状态
```

被封锁的建筑不提供掩护。

### 6.3 暴露压力

建筑的暴露压力由自身和邻域共同决定：

```text
暴露压力 =
自身魔法程度
× 建筑活动强度
× 对普通市民的可见度
- 邻域掩护值
```

建筑类型可以有不同的活动强度：

- 魔法住宅：低
- 私人魔法工坊：中
- 魔法商店和药剂铺：高
- 魔法车站、学院和地标建筑：很高

暴露度是建筑的持久状态值，但每日会根据当前压力继续变化：

```text
下一日暴露度 = 当前暴露度 + 暴露压力 + 事件影响 - 处理效果
```

暴露度可以因为新增普通掩护而下降，也可以因为魔法活动降低而下降。

## 7. 暴露事件与永久封锁

### 7.1 事件生成

当建筑暴露度进入较高区间时，系统按日生成事件概率：

| 暴露度 | 状态 | 效果 |
|---:|---|---|
| 0–49 | 稳定 | 很少产生事件 |
| 50–79 | 异常 | 有概率产生轻微事件 |
| 80–99 | 危险 | 事件频繁，暴露度增长加快 |
| 100 | 帷幕破裂 | 建筑永久封锁 |

事件示例：

- 夜间异常光线被目击
- 建筑内部空间被发现不合理
- 魔法烟雾持续影响邻近街道
- 魔法商品在普通市民手中产生副作用
- 魔法交通造成公共设施异常
- 报纸开始报道该建筑附近的城市怪谈

### 7.2 魔法部自动处理

系统自动按优先级派遣魔法师，不需要玩家或 Agent 手动处理：

1. 优先处理暴露度最高的建筑。
2. 同等风险下优先处理等待时间最长的事件。
3. 可用魔法师不足时，事件保持未解决。
4. 未解决事件会继续推高该建筑暴露度。

有足够魔法师时：

- 事件被平息
- 暴露度下降
- 可能产生少量金币或魔力损失

没有足够魔法师时：

- 事件继续积累
- 建筑进入危险状态
- 最终可能被永久封锁

### 7.3 都市传说地点

建筑被封锁后进入 `sealed` 状态：

- 停止所有金币和魔力产出
- 停止提供普通人口或魔法师人口上限
- 停止吸引人口
- 不能通过普通维修恢复
- 自动增加围栏、封条和警示表现
- 保留在地图上，成为城市中的都市传说地点

除非拆除并重新建造，否则建筑不能恢复功能。

封锁住宅时，原有居民先尝试迁入其他空余住宅。如果城市没有足够住房，部分人口会离开城市，而不是立即消失。

## 8. 实时游戏时间

### 8.1 时间原则

世界时间持续流逝，Agent不再拥有“推进一天”的职责。

系统负责：

- 资源增长
- 建筑生产
- 人口迁移
- 建造进度
- 暴露度更新
- 暴露事件生成
- 魔法部响应
- 猫头鹰日报生成

### 8.2 每日结算

游戏内部可以使用连续小时，但主要在每日边界结算：

```text
时间达到新的一天
    ↓
结算金币、魔力和人口
    ↓
完成到期建设
    ↓
更新每栋建筑暴露度
    ↓
生成暴露事件
    ↓
魔法部自动处理事件
    ↓
记录实际变化
    ↓
生成猫头鹰日报
```

没有玩家或 Agent 操作时，城市照常运行。

### 8.3 离线补算

城市需要保存：

```text
worldTime
lastSettledAt
nextDailyReportAt
```

当城市重新被访问时，系统根据当前时间补算 `lastSettledAt` 之后的变化。长时间离线时，多个日报可以合并成一篇周报或时间摘要，避免产生大量重复文字。

## 9. 玩家卡片

玩家不负责日常建设，而是通过卡片施加方向性干预。

卡片可以：

- 立即生效
- 持续若干游戏日
- 只影响一个建筑或一个邻域
- 影响普通人口、魔法师、金币、魔力、掩护或暴露

卡片示例：

- 城市庆典：提高普通公共建筑的掩护，消耗金币
- 魔法部增援：短时间提高事件处理能力
- 降低魔力活动：指定建筑暂时降低产出和暴露
- 招募普通移民：提高普通人口迁入速度
- 魔法师交流会：提高魔法师吸引力，同时增加暴露压力
- 舆论引导：降低一次异常事件的影响
- 传说营销：把异常包装成城市传说，获得金币但提高该区域长期风险
- 紧急封锁：主动暂停高风险建筑，避免它达到永久封锁阈值

MVP 可以采用“每日报提供若干张卡片，玩家选择一张或跳过”的形式；发牌数量和卡片频率属于可调参数。

## 10. Agent职责

Agent是城市建设者，不是时间控制器，也不是事件处理员。

Agent可以：

- 查询城市快照和猫头鹰日报
- 搜索地块
- 建造和升级建筑
- 连接道路
- 调整普通建筑与高魔法建筑的布局
- 根据暴露风险补充普通公共建筑
- 拆除被封锁建筑并重新规划

Agent不需要：

- 手动派遣魔法师
- 手动推进一天
- 逐个确认系统事件
- 自己生成事实性日报

Agent提交的建设命令可以随时进入队列，并由系统按真实时间推进建设完成。

## 11. 猫头鹰日报

猫头鹰日报完全由系统生成，事实以事件日志为准，不依赖 Agent 在线。

日报固定包含：

1. 日期和总览
2. 金币、魔力和人口变化
3. 新建、完成、封锁和拆除建筑
4. 暴露事件与魔法部处理结果
5. 重要人口变化
6. 当前最危险的建筑
7. 仍待观察的城市变化

日报的文字应由模板和结构化数据生成，不需要模型调用。后续如果需要更强的叙事感，可以增加可选的文字润色层，但不能让润色层成为游戏事实来源。

示例：

> 第十二日。城市获得金币 42，魔力 7。普通人口增加 3，魔法师人口增加 1。东区魔法工坊的暴露度上升至 76，魔法部已派出两名处理员，事件暂时平息。北街市场建造完成，为工坊提供了额外掩护。

## 12. 未来时间加速

时间点数属于后续商业化功能，不属于核心玩法 MVP。

时间点数只能加速世界时间，不能直接赠送资源或跳过规则：

```text
消耗时间点数
    ↓
将目标世界时间向前推进
    ↓
正常结算资源、建设、人口和暴露事件
    ↓
生成日报或日报摘要
```

加速期间仍然可能发生：

- 建筑建成
- 人口迁移
- 暴露事件
- 魔法部处理失败
- 建筑永久封锁

## 13. 暂不实现的方向

以下设计暂时明确排除：

- 独立的里层魔法城市
- 地下或折叠空间的探索流程
- 第一人称或第三人称通勤
- 玩家手动操作魔法师
- 全城统一暴露度 Game Over
- 木材、石材、食物等额外资源
- 每个事件都需要人工确认
- Agent负责推进世界时间

魔法师与普通市民的隐秘关系，第一阶段完全通过以下机制表达：

- 建筑 `magicLevel`
- 普通建筑邻域掩护
- 魔法师人口上限
- 建筑级暴露事件
- 都市传说封锁状态

## 14. MVP验收标准

核心玩法原型至少满足：

- 建筑拥有 `magicLevel`，并能影响外观、成本、产出和暴露压力。
- 普通住宅提高普通人口上限。
- 高魔法住宅提高魔法师人口上限。
- 公共建筑能够提高金币或魔力生产。
- 魔法建筑建造时消耗金币和魔力。
- 金币和魔力都有基础缓慢增长。
- 每栋高魔法建筑拥有独立暴露度。
- 附近低魔法建筑可以提供掩护并降低暴露压力。
- 系统可以按建筑暴露度生成事件。
- 魔法部自动使用可用魔法师处理事件。
- 魔法师不足时，事件会继续积累。
- 暴露度达到阈值后建筑被永久封锁，而不是 Game Over。
- 封锁建筑需要拆除重建才能恢复功能。
- 世界时间在无人操作时继续流逝。
- 系统每天自动生成纯文字猫头鹰日报。
- Agent只负责建设，不负责推进时间或处理事件。
- 玩家可以通过卡片进行方向性干预。
